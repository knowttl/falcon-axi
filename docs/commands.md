## detection summary

```text
falcon-axi detection summary [--severity <name>] [--status <name>] [--product <name>] [--since <window>] [--filter <FQL>]

--severity   one of informational, low, medium, high, critical
--status     one of new, in_progress, closed, reopened
--product    one of epp, idp, mobile, xdr, overwatch, cwpp, ngsiem, thirdparty, data-protection
--since      relative window such as 24h or 7d
--filter     raw FQL, combined with the shorthand filters as in detection list

Counts by severity across matching alerts, including hidden alerts, without listing them.
other_count, when present, counts alerts in buckets omitted by Falcon.
Examples:
  falcon-axi detection summary --since 24h
  falcon-axi detection summary --product idp --status new

This command is read-only and requires only Alerts:read.
```

## detection list

```text
falcon-axi detection list [--severity <name>] [--status <name>] [--product <name>] [--since <window>] [--filter <FQL>] [--limit N] [--cursor <token>] [--all] [--max-rows N] [--fields <names>]

--severity   one of informational, low, medium, high, critical
--status     one of new, in_progress, closed, reopened
--product    one of epp, idp, mobile, xdr, overwatch, cwpp, ngsiem, thirdparty, data-protection; epp is endpoint alerts, idp is Identity Protection
--since      relative window such as 24h or 7d
--filter     raw FQL; + is AND, `,` is OR, values are single-quoted, relative dates are lowercase
--limit      rows in this call (default 20, ceiling 10000)
--cursor     opaque continuation token from a previous call
--all        walk pages; page size is independent of --limit
--max-rows   row budget (default 1000; requires --all)
--fields     extra columns, comma-separated: status, technique, created_timestamp

Filterable fields include severity_name, status, product, tactic, technique, created_timestamp,
and device.hostname.
Identity Protection alerts have no device: their rows show the endpoint they came from as hostname
(or `n/a`) and add account, account_id, device_id, and product columns when the page holds any.
Examples:
  falcon-axi detection list --severity high --since 24h
  falcon-axi detection list --product idp --since 7d
  falcon-axi detection list --filter "severity_name:'Critical'+status:'new'"

This command is read-only and requires only Alerts:read.
```

## detection process

```text
falcon-axi detection process <composite id> [--full]

--full       print command lines without the default 800-character truncation

Show the triggering process, parent, and grandparent recorded on the alert.
Rows contain relation, filename, filepath, cmdline, sha256, and process_id.
triggering_process_graph_id is the alert's graph pivot; this view does not fetch a graph.
Absent ancestors and alerts without a process are stated explicitly.
Examples:
  falcon-axi detection process 'ldt:synthetic-agent:1001'
  falcon-axi detection process 'ldt:synthetic-agent:1001' --full

This command is read-only and requires only Alerts:read.
```

## host logins

```text

The device id is the agent id Falcon calls the AID, as printed by `falcon-axi host list`.
--since      window to read, such as 24h or 7d (default 7d, Falcon's own default)
```

## vuln list

```text
falcon-axi vuln list [--host <device id>] [--severity <name>] [--status <name>] [--since <window>] [--filter <FQL>] [--limit N] [--cursor <token>] [--fields <names>] [--all] [--max-rows N]

--host       device id (AID) whose vulnerabilities to read
--severity   one of low, medium, high, critical
--status     one of open, closed, reopen, expired
--since      created_timestamp within a relative window such as 24h or 7d
--filter     raw FQL; + is AND, `,` is OR, values are single-quoted
--limit      rows in this call (default 20, ceiling 5000)
--cursor     opaque continuation token from a previous call
--all        walk pages; page size is independent of --limit
--max-rows   row budget (default 1000; requires --all)

Filterable fields include aid, cve.id, cve.severity, cve.exprt_rating, cve.exploit_status,
status, and created_timestamp.
Examples:
  falcon-axi vuln list --severity critical --status open
```

## cve show

```text
falcon-axi cve show <CVE-ID>

Reads one CVE from Falcon Intelligence. It is not Spotlight host exposure:
an empty result means CrowdStrike Intelligence has no entry, not that no host is affected.
A CVE identifier matches CVE-<year>-<number>, for example CVE-2021-44228.

Default fields are cve, severity, cvss_v3_score, exploit_status, publish_date, updated,
and description. Related actor, report, threat, and affected-product lists are counts.
This command does not expand those lists. Run `falcon-axi cve list` to find CVEs.

Example: falcon-axi cve show CVE-2021-44228

This command is read-only and requires Vulnerabilities (Falcon Intelligence):read.
That scope is license-gated. Spotlight's Vulnerabilities:read does not satisfy it, and a
scope missing from the API client picker means the tenant has no Falcon Intelligence subscription.
Whether --member-cid carries this scope is unverified.
```

## identity activity

```text
falcon-axi identity activity <account objectGUID or name> [--since <window>]

--since      window to search, such as 24h or 7d (default 24h)

Starts one NG-SIEM search job for an account's Identity Protection events: Active Directory
authentication and service access, LDAP and RPC requests, account changes and audits, SSO
logons, and risk-score changes. It returns the latest 200, newest first.
The account is an objectGUID (account_id in `detection show`), a sAMAccountName, or a UPN.
A name may contain letters, digits, and `. _ @ $ -` only, and is matched in full, ignoring case.
Poll the job with `falcon-axi search status <id>` and cancel it with `falcon-axi search stop <id>`.

Example: falcon-axi identity activity 00000000-0000-0000-0000-000000000000 --since 7d

This command starts a job on the tenant and requires NGSIEM:write.
It changes no identity, account, or detection.
```

## search start

```text
falcon-axi search start --query <CQL> [--repository <name>] [--since <window>] [--wait <seconds>]

--query      the CQL search to run; required
--repository repository or view to search (default search-all)
--since      window to search, such as 24h or 7d (default 24h)
--wait       poll for completion for 1-50 seconds (default: return the job id immediately)

CQL is pipe-based and is neither FQL nor SQL: a filter, then commands.
Start from a tag or field filter and pipe into commands, and bound the result set in the
query itself with `| head(N)` or an aggregate; there is no --limit and no --cursor.
Examples:
  falcon-axi search start --query '#event_simpleName=ProcessRollup2 | head(5)' --wait 30
  falcon-axi search start --query '#event_simpleName=ProcessRollup2 | groupBy([ComputerName], function=count())' --since 7d

This command starts a job on the tenant and requires NGSIEM:write.
Using --wait also requires NGSIEM:read to poll status.
Poll it with `falcon-axi search status <id> --wait 30`; a timeout leaves the job running.
For readable epoch-millisecond @timestamp values, append this CQL stage:
| formatTime("%Y-%m-%dT%H:%M:%SZ", field=@timestamp, as=time, timezone="UTC")
```
